Структура проекта

Проект оформлен как Maven-приложение. В корне находится файл pom.xml, в котором описана сборка проекта, зависимости, запуск тестов, Checkstyle и JaCoCo. Также в корне есть .gitignore и примеры файлов экспорта в CSV и JSON.
Папка .github/workflows содержит файл ci.yml, который настраивает GitHub Actions. При каждом обновлении репозитория автоматически запускается сборка проекта и тесты.
В папке config расположен файл checkstyle.xml с правилами проверки стиля кода. Папка data используется для хранения файлов кошельков пользователей в формате JSON, которые сохраняются при выходе из приложения.
Основной код находится в src/main/java/app. Класс Main является точкой входа в программу, ConsoleApp отвечает за работу с консолью. Классы User, Wallet и Transaction описывают модель данных. Бизнес-логика вынесена в сервисные классы UserService, FinanceService, StorageService и CsvUtil.
Тесты расположены в src/test/java/app. Здесь находятся модульные тесты для сервисов и один интеграционный тест, проверяющий полный сценарий работы приложения.
Папка target создаётся автоматически Maven’ом и содержит скомпилированные классы, отчёты тестов, Checkstyle и JaCoCo.

Как пользоваться сервисом

После запуска приложения в терминале "java -jar target/finance-app-1.0.0.jar" выводится меню авторизации. Пользователю предлагается выбрать действие: зарегистрироваться, войти в систему или выйти из приложения. Выбор осуществляется вводом номера команды.

=== Меню авторизации ===
1. Регистрация
2. Вход
3. Выход из приложения
Выберите действие:

После регистрации или входа пользователь попадает в основное меню приложения. Все дальнейшие действия выполняются через это меню.

=== Главное меню (user) ===
1. Добавить категорию
2. Добавить доход
3. Добавить расход
4. Установить/изменить бюджет категории
5. Показать сводку
6. Фильтр статистики (период/категории)
7. Перевод другому пользователю
8. Экспорт CSV
9. Импорт CSV
10. Экспорт JSON
11. Импорт JSON
12. Выход из аккаунта
13. Выход из приложения
Выберите действие:

При первом входе в систему необходимо создать категории. Для этого выбирается пункт «Добавить категорию» и вводится её название.

При добавлении дохода или расхода приложение последовательно запрашивает данные операции. Пользователь вводит категорию и сумму, при необходимости — описание и дату. Если введены некорректные данные, приложение выводит сообщение об ошибке и предлагает повторить ввод.

Выберите действие: 2
Введите категорию дохода: Еда
Введите сумму дохода: 2000
Дата (yyyy-MM-dd или Enter = сегодня): 
Описание (Enter если пусто): 
Доход добавлен.

Если для категории установлен бюджет, приложение автоматически проверяет его состояние и выводит предупреждение при достижении лимита или перерасходе.

Выберите действие: 3
Введите категорию расхода: Еда
Введите сумму расхода: 7000
Дата (yyyy-MM-dd или Enter = сегодня): 
Описание (Enter если пусто): 
Расход добавлен.
Внимание: Расходы превысили доходы
Внимание: Баланс <= 0
Внимание: Превышен бюджет по категории 'Еда'. Остаток: -4000.00

Команда просмотра статистики выводит сводную информацию по финансам пользователя, включая общий доход, общий расход, текущий баланс и данные по категориям.

Выберите действие: 5

=== Сводка ===
Общий доход: 2000.00
Общий расход: 7000.00
Баланс: -5000.00

Доходы по категориям:
Еда: 2000.00

Расходы по категориям:
Еда: 7000.00

Бюджеты:
Еда: лимит 3000.00, потрачено 7000.00, остаток -4000.00

При экспорте данных приложение запрашивает имя файла и сохраняет данные в выбранном формате. При импорте данные загружаются из указанного файла и заменяют текущий кошелёк пользователя.

Приложение поддерживает перевод денежных средств между пользователями. Для выполнения перевода оба пользователя должны быть зарегистрированы в системе.
В основном меню выбирается пункт перевода средств. После этого пользователю предлагается ввести логин получателя, категорию (долг, оплата ...) и сумму перевода. Перевод оформляется как расход у отправителя и как доход у получателя.

Выберите действие: 7
Кому (логин): freddy
Категория (Enter = Перевод): Долг по учебе
Сумма: 3000
Перевод выполнен.

Тестирование

Для тестирования используется JUnit 5. В проекте есть модульные тесты для основных сервисов, а также интеграционный тест, который проверяет полный сценарий работы пользователя.
Тестами проверяются:
- добавление доходов и расходов,
- работа с бюджетами,
- авторизация пользователей,
- импорт и экспорт данных,
- обработка ошибок.

Для запуска тестов и проверки проекта используется команда: mvn clean verify
Во время сборки автоматически запускаются тесты, проверяется стиль кода с помощью Checkstyle и анализируется покрытие кода тестами с помощью JaCoCo.

Сборка проекта

Проект собирается с помощью Apache Maven. В pom.xml настроены все необходимые плагины для компиляции, тестирования и проверки качества кода. CLI-классы (Main и ConsoleApp) исключены из расчёта покрытия тестами, так как они предназначены только для работы с вводом пользователя.
При успешной сборке Maven выводит сообщение BUILD SUCCESS.



Документация по модулям проекта

Main.java

Класс Main содержит метод public static void main(String[] args). В этом методе создаётся объект ConsoleApp и вызывается метод запуска приложения. Вся логика работы приложения вынесена в другие классы, Main используется только как точка входа.

ConsoleApp.java

Класс ConsoleApp реализует пользовательский интерфейс в терминале. В нём находится основной цикл чтения команд пользователя, вывод меню авторизации и главного меню, а также обработка выбранных пунктов. В зависимости от команды ConsoleApp вызывает методы сервисных классов, такие как UserService, FinanceService, StorageService и CsvUtil. Самостоятельной бизнес-логики этот класс не содержит.

UserService.java

Класс UserService отвечает за работу с пользователями. В нём реализованы методы регистрации, входа и выхода пользователя. Метод login(...) загружает кошелёк пользователя с помощью StorageService.loadWallet(...), а метод logout() сохраняет данные кошелька через StorageService.saveWallet(...). Также класс хранит информацию о текущем авторизованном пользователе.

User.java

Класс User представляет пользователя системы. Он содержит поля для логина, пароля и кошелька (Wallet). Класс используется как модель данных и передаётся между сервисами. Методы класса используются для получения и установки кошелька пользователя.

Wallet.java

Класс Wallet хранит все данные, связанные с финансами пользователя. В нём находятся коллекции операций (List<Transaction>), категорий (Set<String>) и бюджетов (Map<String, Double>). Класс предоставляет методы доступа к этим данным и используется в FinanceService для добавления операций и расчёта статистики.

Transaction.java

Класс Transaction описывает одну финансовую операцию. Он содержит поля категории, суммы, типа операции (доход или расход), даты и описания. Объекты этого класса создаются в FinanceService и добавляются в кошелёк пользователя.

FinanceService.java

Класс FinanceService содержит основную бизнес-логику приложения. В нём реализованы методы addIncome(...), addExpense(...), setBudget(...), а также методы подсчёта общей суммы доходов и расходов. В этом же классе выполняются проверки превышения бюджета, достижения 80% лимита и ситуации, когда расходы превышают доходы. Для формирования статистики используется внутренний класс FilterResult.

StorageService.java

Класс StorageService отвечает за работу с файлами JSON. Методы saveWallet(...) и loadWallet(...) используются при выходе и входе пользователя. Для сериализации и десериализации используется библиотека Gson, а для корректной работы с датами реализован адаптер LocalDateAdapter. Также класс поддерживает ручной импорт и экспорт данных в формате JSON.

CsvUtil.java

Класс CsvUtil реализует экспорт и импорт данных кошелька в формате CSV. Метод exportCsv(...) сохраняет операции, категории и бюджеты в файл, а метод importCsv(...) восстанавливает объект Wallet из CSV-файла. В классе предусмотрена обработка некорректных строк и пустых значений, чтобы приложение не завершалось с ошибкой.

Тестовые классы

Тесты расположены в src/test/java/app. Для каждого сервисного класса реализованы отдельные тесты, например UserServiceTest, FinanceServiceTest и StorageServiceTest. Дополнительные тесты (More*Test) покрывают граничные случаи и ветви кода, связанные с обработкой ошибок. Интеграционный тест IntegrationFlowTest проверяет полный сценарий работы приложения, включая авторизацию, добавление операций и сохранение данных.
